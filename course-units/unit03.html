Teoría

Pila: el último en entrar es el primero en salir.

Una pila (en inglés, stack) es una estructura lineal: los elementos están ordenados uno tras otro. La diferencia con un arreglo es que en una pila las inserciones y eliminaciones ocurren en un solo extremo, llamado tope. Por eso su comportamiento se llama LIFO (Last In, First Out): el último en entrar es el primero en salir.

Analogía

Una torre de platos: solo puedes tomar el de arriba. El último que colocaste es el primero que retiras. No puedes sacar el plato de abajo sin quitar los de arriba.

Operaciones básicas

  • push(x): inserta x en el tope (meter).
  • pop(): elimina y devuelve el tope (sacar).
  • peek() / top(): consulta el tope sin eliminarlo (mirar).
  • isEmpty(): ¿está vacía?
  • size(): cantidad de elementos.
💡 Todas las operaciones sobre el tope son O(1): no dependen de cuántos elementos haya.

Usos típicos

Deshacer/rehacer, evaluación de expresiones, llamadas a funciones, navegación atrás en el navegador.

Regla

No se puede insertar ni eliminar en medio ni en la base sin sacar antes lo de arriba.

Error común

Hacer pop() sobre una pila vacía: subdesbordamiento (underflow).

Laboratorio

Pila con arreglo: un índice que sube y baja.

Usamos un arreglo de capacidad fija y un índice top que apunta a la próxima posición libre. Si top llega a la capacidad, la pila está llena (desbordamiento u overflow). Si top es 0, está vacía (subdesbordamiento o underflow).

Capacidad 5 · pila vacía

Pila vacía. Pulsa push para insertar.

Implementación

class PilaArreglo<T> {
  private Object[] datos;
  private int top; // próximo libre

  PilaArreglo(int cap) {
    datos = new Object[cap];
    top = 0;
  }

  void push(T x) {
    if (top == datos.length)          // pila llena
      throw new IllegalStateException("overflow");
    datos[top++] = x;
  }

  T pop() {
    if (top == 0)                   // pila vacía
      throw new IllegalStateException("underflow");
    T x = (T) datos[--top];
    datos[top] = null; // liberar
    return x;
  }

  T peek() {
    if (top == 0) return null;
    return (T) datos[top - 1];
  }
}
⚠️ Desbordamiento (overflow): top == capacidad. Subdesbordamiento (underflow): top == 0.
Laboratorio

Pila dinámica: el tope es la cabeza.

Recordando lo esencial: un nodo guarda un dato y una referencia al siguiente; head es el primer nodo. Si usamos una lista enlazada simple como pila, el tope es la head. push inserta al inicio y pop elimina el primer nodo. Ambas operaciones son O(1).

Estado de la pila dinámica

Pila vacía (head = null).

Implementación

class Nodo<T> {
  T dato;
  Nodo<T> siguiente;
  Nodo(T d) { dato = d; }
}

class PilaDinamica<T> {
  private Nodo<T> head; // tope
  private int size;

  void push(T x) {
    Nodo<T> n = new Nodo<>(x);
    n.siguiente = head;
    head = n;
    size++;
  }

  T pop() {
    if (head == null) return null;
    T x = head.dato;
    head = head.siguiente;
    size--;
    return x;
  }

  T peek() {
    return head == null ? null : head.dato;
  }
}
💡 Ventaja: no hay límite fijo de capacidad, así que no hay desbordamiento por tamaño. Costo: cada nodo ocupa más memoria que una celda de arreglo.
Teoría

Cola: el primero en entrar es el primero en salir.

Una cola (en inglés, queue) es una estructura lineal en la que se inserta por un extremo llamado final (en inglés, rear) y se elimina por el otro extremo llamado frente (en inglés, front). Su comportamiento se llama FIFO (First In, First Out): el primero en entrar es el primero en salir.

Analogía

Una fila del banco: el primero que llegó es el primero que es atendido. Nadie se cuela por el medio.

Operaciones básicas

  • enqueue(x): inserta x al final (encolar).
  • dequeue(): elimina y devuelve el frente (desencolar).
  • front() / peek(): consulta el frente sin eliminarlo.
  • isEmpty(): ¿está vacía?
  • size(): cantidad de elementos.
💡 enqueue y dequeue bien implementados son O(1).

Usos típicos

Turnos, impresión, buffers (memorias temporales que guardan datos mientras se procesan), recorrido BFS (búsqueda en anchura: visitar primero los vecinos más cercanos).

Regla

No se accede al medio: solo al frente para eliminar y al final para insertar.

Error común

dequeue() sobre cola vacía: subdesbordamiento (underflow).

Laboratorio

Cola con arreglo: cuidado con el desperdicio.

Si solo avanzamos los índices front (frente) y rear (final) sin volver al inicio, el arreglo se "gasta": las primeras posiciones quedan vacías para siempre. La solución es una cola circular: cuando un índice llega al final del arreglo, vuelve a 0. Eso se logra con el operador módulo (%): (i + 1) % capacidad da 0 cuando i es la última posición.

Cola circular (capacidad 6)

Cola vacía (frente = final = 0).

Implementación

class ColaCircular<T> {
  private Object[] datos;
  private int front, rear, size;

  ColaCircular(int cap) {
    datos = new Object[cap];
    front = rear = size = 0;
  }

  void enqueue(T x) {
    if (size == datos.length)       // cola llena
      throw new IllegalStateException("llena");
    datos[rear] = x;
    rear = (rear + 1) % datos.length; // vuelve a 0 si llega al final
    size++;
  }

  T dequeue() {
    if (size == 0)                // cola vacía
      throw new IllegalStateException("vacía");
    T x = (T) datos[front];
    datos[front] = null;
    front = (front + 1) % datos.length;
    size--;
    return x;
  }

  T front() {
    return size == 0 ? null : (T) datos[front];
  }
}
⚠️ Regla de oro: usa size para distinguir "llena" de "vacía". Si comparas solo front == rear, ambos estados son indistinguibles (en ambos casos los índices coinciden).
Laboratorio

Cola dinámica: dos referencias, dos extremos.

Recordando lo esencial: head es el primer nodo y tail el último. Con una lista simple, head es el frente (por donde se saca) y tail es el final (por donde se inserta). Así enqueue y dequeue son O(1).

Estado de la cola dinámica

Cola vacía (head = tail = null).

Implementación

class ColaDinamica<T> {
  private Nodo<T> head, tail;
  private int size;

  void enqueue(T x) {
    Nodo<T> n = new Nodo<>(x);
    if (head == null) { head = tail = n; }
    else { tail.siguiente = n; tail = n; }
    size++;
  }

  T dequeue() {
    if (head == null) return null;
    T x = head.dato;
    head = head.siguiente;
    if (head == null) tail = null; // cola quedó vacía
    size--;
    return x;
  }

  T front() {
    return head == null ? null : head.dato;
  }
}
💡 Detalle: al eliminar el último nodo hay que poner tail = null; si no, tail queda apuntando a un nodo fuera de la lista.
Teoría y práctica

Cola con prioridad: no siempre gana el primero.

En una cola con prioridad, cada elemento tiene una prioridad. Al hacer dequeue, sale el de mayor prioridad; si hay empate, sale el más antiguo (FIFO entre iguales). No es una cola FIFO pura: el orden de salida depende de la prioridad, no solo del orden de llegada.

Simulación

Cola vacía. Inserta elementos con prioridad.

Implementaciones

  • Lista ordenada: insertar mantiene orden por prioridad; dequeue O(1).
  • Montículo (heap): un árbol binario especial donde el padre siempre es mayor (o menor) que sus hijos; permite insertar y extraer en O(log n). Es la base de PriorityQueue en Java.
  • Lista desordenada: inserción O(1), dequeue O(n) buscando el máximo.
// PriorityQueue: cola con prioridad de la librería Java
var pq = new PriorityQueue<Tarea>(
  Comparator.comparingInt(t -> -t.prioridad)); // mayor prioridad primero
pq.add(new Tarea("A", 1));
pq.add(new Tarea("B", 3));
pq.poll(); // devuelve B (prioridad 3)
💡 Ejemplo real: una sala de emergencias atiende primero al paciente crítico, no al que llegó antes. Eso es una cola con prioridad.
Síntesis

Pila vs. cola: mismo almacenamiento, distinto orden.

Pila (último en entrar, primero en salir)

  • Inserción y eliminación en el mismo extremo (tope).
  • push y pop en O(1).
  • Usos: deshacer, recursión, evaluación de expresiones.
  • Error típico: underflow al hacer pop en vacía.

Cola (primero en entrar, primero en salir)

  • Inserción en el final, eliminación en el frente.
  • enqueue y dequeue en O(1) con tail o arreglo circular.
  • Usos: turnos, buffers, BFS.
  • Error típico: underflow al hacer dequeue en vacía.

Aplicación

Una pila resuelve los paréntesis balanceados.

Recorre la expresión: si ves (, [ o {, lo apilas; si ves un cierre, desapilas y verificas que coincida. Al final, la pila debe quedar vacía.

Expresión: {[()]}

Pulsa "Siguiente carácter" para procesar.
// Deque = "double-ended queue" (cola doble).
// ArrayDeque es una implementación de Deque basada en arreglo.
// Se usa como pila porque tiene push/pop.
boolean balanceado(String s) {
  Deque<Character> pila = new ArrayDeque<>();
  for (char c : s.toCharArray()) {
    if (c == '(' || c == '[' || c == '{')
      pila.push(c);
    else if (c == ')' || c == ']' || c == '}') {
      if (pila.isEmpty()) return false;
      char a = pila.pop();
      if (!coincide(a, c)) return false;
    }
  }
  return pila.isEmpty();
}
✅ Complejidad: O(n) en tiempo (se recorre cada carácter una vez) y O(n) en espacio en el peor caso.

Una cola atiende turnos en orden de llegada.

Simulamos una fila de atención: los clientes llegan y se atienden. El primero en llegar es el primero en salir.

Cola vacía. Pulsa "Llega cliente" para iniciar.

Reglas de la simulación

  • Cada "Llega cliente" crea un turno con número creciente.
  • Cada "Atender" hace dequeue y muestra el turno atendido.
  • Si la cola está vacía, "Atender" reporta underflow (subdesbordamiento).
💡 Este patrón es la base de sistemas de tickets, impresión y buffers de red.

Reto: editor con deshacer y rehacer.

Implementa un editor simple: cada cambio se apila en la pila deshacer; al deshacer, el estado se mueve a la pila rehacer. Al rehacer, vuelve a deshacer.

Plan de solución

1

Dos pilas: deshacer y rehacer.

2

Cada acción se apila en deshacer y limpia rehacer.

3

Deshacer mueve de deshacer a rehacer.

class Editor {
  private Deque<String> deshacer = new ArrayDeque<>();
  private Deque<String> rehacer  = new ArrayDeque<>();
  private String actual = "";

  void escribir(String s) {
    deshacer.push(actual);   // guardar estado anterior
    rehacer.clear();         // al escribir, se pierde el rehacer
    actual += s;
  }

  void deshacerAccion() {
    if (deshacer.isEmpty()) return;
    rehacer.push(actual);
    actual = deshacer.pop();
  }

  void rehacerAccion() {
    if (rehacer.isEmpty()) return;
    deshacer.push(actual);
    actual = rehacer.pop();
  }
}

Repaso

La restricción de acceso es la que define la estructura.

Pilas y colas no son "arreglos con otro nombre": son TAD cuyo contrato limita las operaciones a los extremos. Esa restricción es lo que las hace útiles.

Errores a evitar

  • Desbordamiento (overflow): insertar en una estructura llena.
  • Subdesbordamiento (underflow): sacar de una estructura vacía.
  • Confundir frente y final: se saca por el frente, se inserta por el final.

Antes de dar por terminado

  • Verifica índices y null.
